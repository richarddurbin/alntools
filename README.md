# alntools
utilities for processing .1aln files from [FastGA](https://github.com/thegenemyers/FASTGA), [FasTAN](https://github.com/thegenemyers/FASTAN) etc.

Make with `make` and install with `make install`.  If you want to install elsewhere than the default `~/bin` directory then `make DESTDIR=/your/preferred/location`.

Current contents are:

## tanbed

converts a .1aln file generated by [FasTAN](https://github.com/thegenemyers/FASTAN) into a [BED](https://en.wikipedia.org/wiki/BED_(file_format)) file.  Example usage is: 

```
> tanbed mGorGor-tan.1aln > mGorGor-tan.bed
read GDB from mGorGor-tan.1aln : 26 seqs 28 contigs (2 gaps), totSeq 3545850636 totCtg 3543850636 (99.944%)
processed 636143 alignments total length 708296862 from mGorGor-tan.1aln length 3545850636 (20.0 %)
```

## tancons

extracts consensus sequences for tandem repeat arrays found by [FasTAN](https://github.com/thegenemyers/FASTAN), from the `.1ano` file it writes.  The consensus of an array is built from the copies in the FasTAN parse that are exactly one unit apart.  It can find the consensus of every array with enough such copies, of the array of a given unit size with the most copies, or of one chosen array.  Example usage is (this uses a small file `mDDtail.fa` containing the last 15 sequences of a genome):

```
> FAtoGDB mDDtail.fa
> FasTAN -mp mDDtail
> tancons -u 1579 mDDtail.1ano
tandem repeat of unit 1579 with most exact copies (4) is NW_027193229.1:0-16000:0:16000
>cons1579#NW_027193229.1:0-16000:0-16000#4#88.0
cgctttcttgtgacctggccgcaacaccgcaggatggcttcaggccctaatctggttccggcacggcacgctgagcctttggttatttcctcttcctggtgggaaatgag...
> tancons -m 4 -o cons.fa mDDtail.1ano
> grep '>' cons.fa
>cons167#NW_027193230.1:0-16000:0-16000#6#75.7
>cons1856#NW_027193232.1:0-15365:0-15365#6#99.8
>cons1580#NW_027193226.1:0-18000:0-18000#5#98.1
>cons1579#NW_027193229.1:0-16000:0-16000#4#88.0
>cons1580#NW_027193235.1:0-14000:3-14000#4#91.5
> tancons
Usage: tancons [-o <output_file>] [-u <unit_size>] [-s <sequence_file>] [-m <min_count>] [-c <seq>:<start>-<end>] <file[.1ano]>
```

(The consensus sequence in the first record is cut short here.)  The **FasTAN** command must have used options `-m` to make a `.1ano` file and `-p` to create `P` "parse" lines in the `.1ano` file.  Masking with `-m` requires a GDB, which you can make from a fasta file with `FAtoGDB` from the [FastGA package](https://github.com/thegenemyers/FASTGA), and the name given to **FasTAN** must have no suffixes, i.e. without `.fa` or `.fa.gz`.  You can also use `-a` to generate a `.1aln` file but this is not required by **tancons**.  The `.1ano` ending of the file name can be left off, or you can give the full path name.  Only arrays with a unit size of at least 20 are considered.

There are three ways to choose the arrays to report.  By default **tancons** reports every array with at least `-m` copies (default 100) that are exactly one unit apart in the FasTAN parse; `-m` must be at least 2, and it is not used in the other two modes.  With `-u` it reports only the array of that unit size with the most exact-unit copies, and writes a line saying which one it found to stderr.  With `-c` it reports only the array in sequence `<seq>` that starts at coordinate `<start>`.  If `<end>` is also given and is not 0 then it must match the end of the array as well.  If the sequence name itself contains a `:` then escape it with a backslash, e.g. `-c 'scaffold\:1:100-200'`.  The sequence identifier and start coordinate are enough to identify an array, because the end coordinates in the `.1aln` and `.1ano` files generated by FasTAN do not match.

The output is a fasta file, written to standard output, so you can pipe it into a filename; alternatively use option `-o` to specify the output file name.  There is one record for each array, in order of decreasing number of copies.  The record name is `cons<unit>#<seq>:<start>-<end>#<count>#<match>`, giving the unit size, the sequence and coordinates of the array, the number of exact-unit copies used, and the average percent of the bases in those copies that agree with the consensus.  The program tries to find the sequence file name from the .1ano header, but if this fails you can specify the sequence file name on the command line using `-s`.

Options are:

| Option | Meaning |
|---|---|
| `-o <file>` | write the fasta output to this file (default standard output) |
| `-u <n>` | report only the array of unit size `n` with the most exact-unit copies |
| `-c <seq>:<start>-<end>` | report only the array in sequence `seq` starting at `start` (and ending at `end`, if given and not 0) |
| `-m <n>` | minimum number of exact-unit copies for an array to be reported when neither `-u` nor `-c` is given (default 100, at least 2) |
| `-s <file>` | the sequence file, if its name can not be found from the `.1ano` header |

## satmatch

matches and clusters a set of candidate sequences - for example the tandem-repeat unit consensus sequences produced by running **tancons** at many different loci - by all-against-all pairwise alignment (Needleman-Wunsch), to work out which candidates represent the same underlying satellite/repeat family and to pick a single representative sequence for each family. Every pair is checked in both orientations, since a repeat unit could have been recorded from either strand; with option `-loop` the second sequence of the pair is also treated as circular, so a match can start at any rotation, which is useful because tandem repeat unit sequences are often recorded starting at an arbitrary phase. Example usage is:

```
> satmatch -loop -fa satfams.fa candidates.fa
8 sequences, total length 160
found 0 frequency-based clusters
threshold 0.680
  new mark 1: 0 (20) to 1 (20) score 0 thresh 3
  link mark 1: 0 (20) to 2 (20) score 0 thresh 3
  new mark 2: 3 (20) to 4 (20) score 0 thresh 3
  new mark 3: 6 (20) to 7 (20) score 0 thresh 3
cluster 1 count 3 minLen 20 repLen 20 acgtggcattacgggcatta
  unitA	20	0
  unitA-rot	20	0
  unitA-rc	20	0
cluster 2 count 2 minLen 20 repLen 20 ggggccccaaaattttggcc
  unitB	20	0
  unitB-rot	20	0
cluster 3 count 2 minLen 20 repLen 20 aaacccgggtttaaacccgg
  unitD	20	0
  unitD-rot	20	0
```

The first lines (the number of sequences, the number of composition-based preclusters, which is currently only reported, and the threshold) are written to stderr, and the cluster information to standard output.  On startup satmatch aligns many pairs of random sequences using the chosen scoring parameters to estimate a length-scaled significance threshold (reported as `threshold 0.680` above); two input sequences are then linked into the same cluster if their alignment score falls at or below this factor times the length of the longer of the two, minus 10 (the `new/link/merge mark` lines record clusters being built up as all pairs are scanned, with the threshold used).  For each cluster found, satmatch prints a summary line with the number of members (`count`), the length of the shortest member (`minLen`), and the length and sequence of the chosen representative (`repLen`, chosen as the member with lowest total alignment score to the rest of the cluster, close to `minLen`), followed by one line per member giving its name, length, and alignment score to the representative.  The representatives are written by `-fa` as fasta records named `sat-<cluster>-<length>`, as above (`>sat-1-20`, `>sat-2-20`, `>sat-3-20`), and this file can be used directly as the unit sequences for **satscan**.

Options are:

| Option | Meaning |
|---|---|
| `-ti <n>` | transition mismatch penalty (default 1) |
| `-tv <n>` | transversion mismatch penalty (default 2) |
| `-gap <n>` | gap penalty per position (default 3) |
| `-loop` | treat the second sequence of each pair as circular, so a match can start at any rotation |
| `-fa <file>` | write the representative sequence of each cluster found to a fasta file |
| `-sf <file>` | write one line per sequence pair to a tab-separated file, with columns for the two names and lengths, the score, the orientation (`+` or `-`) and, with `-loop`, the best rotation offset |
| `-random <n> <len>` | instead of reading `<seqfile>`, generate and use `n` random sequences of length `len` - useful for exploring the significance threshold |

## satscan

scans a genome sequence file for arrays of satellite repeat units, for example the representative unit sequences written by `satmatch -fa`, and reports each array that matches a unit.  Each unit is tried on both strands.  The units can be given as a FASTA (or other sequence) file, or as a ONEcode `.1seq` or `.1lib` repeat library file; from a `.1lib` file only entries whose type (`Y` line) starts with "tandem" are used, while entries with no type are used as for FASTA.

A match starts where 32bp of the target scores positively, with no gaps, against the first 32bp of the unit, and is then extended by affine-gap dynamic programming around the unit treated as a circle, so it can run through any number of copies of the repeat and tolerate substitutions and indels.  It ends at the best scoring point at which the next 32bp of the target again score positively, without gaps, against the last 32bp of the unit, so every match is a whole number of copies of the unit.  To stop a match running on through unrelated sequence, any alignment that falls more than an x-drop below the best score the match has reached so far is abandoned: the x-drop is the larger of `-xmin` (default 200) and `-xfac` (default 2.0) times the unit length.  So a long stretch of poor similarity ends a match, and the array beyond it is reported as a separate match.  Matches are reported if their score is above `-smin`.

By default satscan uses a hierarchical scoring scheme, to avoid false positives in regions whose base composition happens to suit a unit, for example purine-rich sequence for a purine-rich unit.  There are three schemes of increasing strictness, all with a match score of +2: weak (2,-1,-3,-15,-1), medium (2,-2,-4,-20,-2) and strong (2,-3,-6,-25,-2), giving the match, transition, transversion, gap open and gap extend scores.  For each unit and strand, and each target sequence, satscan finds the regions where the expected score of the unit against random sequence of the region's composition is above -1 per base for the weak scheme, and scans those regions with the medium scheme; within those it finds where medium is also unsafe and uses the strong scheme, and where even strong is unsafe no match may start or continue.  Elsewhere the weak scheme is used.  The rationale, the method and the simulations behind the choice of schemes and threshold are described in [satscan-scoring.md](satscan-scoring.md).  Giving `-score` instead applies a single scheme everywhere, with no masking.  Example usage is, for the human genome and the 171bp centromeric alpha satellite unit:

```
> satscan -o mHomSap-cen.tsv -bed mHomSap-cen.bed mHomSap-cen.fa mHomSap.fa.gz
read in 1 query sequences, total length 171 bp
chr3 length 201105948: 199177 starts, 32 matches, total match length 2642064, 8.85 s
chr2 length 242696752: 240625 starts, 15 matches, total match length 2496674, 9.93 s
chr4 length 193574945: 204646 starts, 14 matches, total match length 3836542, 9.31 s
...
processed 25 target sequences, total length 3117292070 bp
found 3022340 starts, 1150 matches, total match length 83414300 bp
(after removing 4 matches ending where a better one of the same query ends)
user	179.175281	system	0.623519	elapsed 26.071777	alloc_max 3206 MB	max_RSS	3444883456
> head -3 mHomSap-cen.tsv
chr1	103897763	103911559	cen-171	7788	9679	+	171,341,512,684,...	w
chr1	121619161	121788063	cen-171	191729	136828	-	167,336,504,674,...	w
chr1	121790397	121795996	cen-171	6691	4608	-	170,338,509,680,...	w
> head -3 mHomSap-cen.bed
chr1	103897763	103911559	cen-171	701	+
chr1	121619161	121788063	cen-171	810	-
chr1	121790397	121795996	cen-171	823	-
```

The progress lines are written to stderr, one for each target sequence as its scan finishes (so not necessarily in file order), giving the number of start windows found, the number of matches reported, their total length, and the wall time for that sequence.  The results are collected, sorted by target in file order and then by start, and written at the end.  For each unit and strand that needed a stricter scheme somewhere, stderr also reports the number and total length of the regions scanned with the medium and strong schemes, and of the regions where no match was allowed; there are none for the alpha satellite unit above.

Each line of the main output has nine tab-separated columns: the target name, the start (0-based) and end (exclusive) of the match in the target, the name of the unit sequence, the alignment score, the number of exact base matches in the alignment, the strand, which is `-` if the reverse complement of the unit matched, the parse of the match into copies of the unit, and the scoring schemes used for the match, as some of `w`, `m` and `s` for weak, medium and strong, or `u` if `-score` was given.  The parse is a comma-separated list of the internal copy boundaries, i.e. the start of each copy after the first, relative to the start of the match, or `.` if the match is a single copy; the lists are truncated with `...` in the example above.  A copy begins where the alignment reaches the start of the unit, so its boundaries depend on the rotation of the unit sequence.  The parse uses the same convention as the `P` lines that FasTAN writes in `.1ano` files.

Percent identity can be calculated as 100 * (exact matches) / (end - start).  This measures exact matches against the span of the target, so bases of the unit that are skipped by a gap do not add to the denominator.  Matches from different units, or from the two strands of one unit, can overlap, but if two matches of the same unit on the same strand end at the same place then only the better one is kept, and the number removed is reported on stderr.

With `-bed <file>` a standard [BED](https://en.wikipedia.org/wiki/BED_(file_format)) file with six columns is also written: the target, start, end, unit name, the identity in parts per thousand, `(int)(1000*matches/(end-start))`, in the score column, and the strand.  If `-bed` is given without `-o` then nothing is written to standard output; if both are given then both files are written.

Tied alignments are resolved in favour of more exact matches.  The sequences are scanned by `-T` threads (default 8), each working on one target sequence at a time, so the time is limited by the longest sequence; the results are the same for any number of threads.  Up to about two sequences per thread are held in memory at once.  As an indication of speed, scanning the 3.1Gb human genome for the single 171bp unit above took about 26 seconds with the default 8 threads, and for 12 units of 20 to 171bp about 3 minutes.

Options are:

| Option | Meaning |
|---|---|
| `-o <file>` | write the main output to this file (default standard output, unless `-bed` is given) |
| `-bed <file>` | also write BED6 output to this file |
| `-score <m>,<ti>,<tv>,<go>,<ge>` | use this one scoring scheme everywhere instead of the hierarchical schemes: match, transition, transversion, gap open and gap extend scores, e.g. `-score 1,-1,-2,-7,-1` |
| `-smin <n>` | minimum score to report a match (default 50) |
| `-xmin <n>` | minimum x-drop (default 200) |
| `-xfac <x>` | the x-drop is the larger of `-xmin` and this times the unit length (default 2.0) |
| `-T <n>` | number of scanning threads (default 8) |

## gdbmask

masks a .1gdb file as used by [FastGA -M](https://github.com/thegenemyers/FASTGA) with a bed file, as for example generated by **tanbed** from [FasTAN](https://github.com/thegenemyers/FASTAN) output.  Example usage is: 

```
> gdbmask mGorGor.1gdb mGorGor-tan.bed
read GDB from mGorGor.1gdb : 26 seqs 28 contigs (2 gaps), totSeq 3545850636 totCtg 3543850636 (99.944%)
read 636143 bed lines from mGorGor-tan.bed
wrote GDB to mGorGor.1gdb : 26 seqs 28 contigs (2 gaps), totSeq 3545850636 totCtg 3543850636 (99.944%), 636143 masks totMask 708296862 (20.0%)
!! rerun GIXmake mGorGor.1gdb to apply new mask
```

Note that, as requested in the final line of the output, you need to run GIXmake again from the [FastGA package](https://github.com/thegenemyers/FASTGA) in order for this masking to take effect in subsequent `FastGA` runs, and you also need to remember to set the `-M` option for "use soft Masks" when running `FastGA`.

By default `gdbmask` overwrites the given `.1gdb` file.  If you wish to keep that and write a new `.1gdb` file then you can use option `[-o newfile.1gdb]`, but for downstream tools to subsequently use the resulting `newfile.1gdb` you will need to create by copying (or linking) a corresponding hidden `.newname.bps` file that contains the 2-bit compressed sequence.

## taco

TAndem repeat COmpresses a .fa.gz file using coordinates from a `.1aln` file made with [FasTAN](https://github.com/thegenemyers/FASTAN), leaving just the first unit of each tandem repeat. The idea is to use the resulting compressed sequences in subsequent genome alignments, e.g. using [FastGA](https://github.com/thegenemyers/FASTGA). The reasoning behind this is that tandem repeats expand and contract very rapidly, so are likely not to be the same length between two otherwise alignable sequences - in fact because of this expansion/contraction and gene conversion it may well be that copies within a sequences are more closely related to each other than copies between sequences. Also, pragmatically aligners including FastGA can become very inefficient when aligning tandem repeats to each other, exploring and potentially re-exploring exponentially many similar alternatives.  Example usage is: 

```
> taco
Usage: taco [-o <outFileName>] <input.1aln> <seqFile>
  taco stands for 'TAndem COmpress' (cf hoco for 'HOmopolymer COmpress')
  input.1aln should be created by FasTAN and the names and lengths must match to seqFile
  default outFileName is <seqFile-stem>-taco.1seq;  user given outFileName can end in .fa or .fa.gz or .1seq
> taco mGorGor-tan.1aln mGorGor.fa.gz
read GDB from mGorGor-tan.1aln : 26 seqs 28 contigs (2 gaps), totSeq 3545850636 totCtg 3543850636 (99.944%)
> seqstat mGorGor.fa.gz
fasta file, 26 sequences >= 0, 3545850636 total, 136378870.62 average, 16412 min, 243847345 max
> seqstat mGorGor-taco.fa.gz
fasta file, 26 sequences >= 0, 2872001354 total, 110461590.54 average, 16412 min, 223911933 max
```

By default taco converts `XX.fa.gz` to `XX-taco.fa.gz`. Option `-o <name.fa.gz>` will write an alternative file name.

As of 16/11/2025, taco writes out a warning for each repeat in the input `.1aln` file that is contained within the first instance of another repeat, and does not compress it. There are not so many of these and they are typically short dinucleotide to tetranucleotide repeats. I aim to correctly compress these nested repeats and remove this warning. Also, there is not yet a tool to map the results of aligning taco sequences back into the original reference coordinates.

## svfind

retrieves large insertions and deletions from a .1aln file.  Example usage is:

```
> svfind -a ~/tmp/dmel-dmau-a.1sv -b ~/tmp/dmel-dmau-b.1sv dmel-dmau.1aln
read 130445 overlaps
user	0.100205	system	0.006640	elapsed 0.108578	alloc_max 6 MB	max_RSS	19562496
wrote 3355 insertions in ../Drosophila_melanogaster/Dmela-FKT.1gdb to /Users/rd109/tmp/dmel-dmau-a.1sv
user	0.696388	system	0.016602	elapsed 0.713271	alloc_max 107 MB	max_RSS	86114304
wrote 3438 insertions in ../Drosophila_mauritiana/Dmaur-FKT.1gdb to /Users/rd109/tmp/dmel-dmau-b.1sv
user	0.685140	system	0.014473	elapsed 0.699762	alloc_max 208 MB	max_RSS	71139328
Total resources used: user	1.481736	system	0.037810	elapsed 1.521707	alloc_max 208 MB	max_RSS	176816128
```
Note that the outputs are ONEcode files of type .1sv.  Run `ONEview -H outfile.1sv` for header information, and `ONEview -h outfile.1sv` for the results data.

There are lots of options.  Ask Pio Sierra <mailto:pas211@cam.ac.uk> for further information about them if you are interested in modifying them!
